Práce se soubory a adresáři

Příkaz Popis / Příklady
pwdVypíše aktuální pracovní adresář (Print Working Directory).
lsVypíše obsah adresáře. ls -la (detailní výpis včetně skrytých).
cd [cesta]Změna adresáře. cd .. (o úroveň výš), cd ~ (domovský), cd - (předchozí).
mkdir [nazev]Vytvoří novou složku. mkdir -p slozka/podslozka vytvoří celou cestu.
rm [soubor]Smaže soubor. rm -r [slozka] smaže složku rekurzivně.
cp [zdroj] [cil]Kopíruje soubor. cp -r [zdroj_slozka] [cil] rekurzivně kopíruje složku.
mv [zdroj] [cil]Přesune nebo přejmenuje soubor/složku.
touch [soubor]Vytvoří nový prázdný soubor nebo aktualizuje čas modifikace.
cat / lesscat vypíše celý soubor, less otevře stránkovatelný náhled.
grep "[text]"Vyhledává text v souboru. grep -ri "Search" . (rekurzivně bez ohledu na velikost písem).

Příkaz Popis / Příklady

du -sh [slozka]Spočítá a zobrazí velikost konkrétní složky.
free -hZobrazí stav RAM a SWAPu.
sudo apt update && sudo apt upgradeAktualizuje balíčky v systému (Ubuntu/Debian).

Uživatelé a přístupová práva

Conventional Commits (v1.0.0)

Standard pro přehledné a automatizovatelné commit zprávy.

<type>[&optional scope]: <description>

[optional body]

[optional footer(s)]
Typ SemVer Popis
featMINORPřidání nové funkcionality do aplikace.
fixPATCHOprava chyby / bugu v kódu.
docs-Změny pouze v dokumentaci.
style-Úpravy stylu kódu (středníky, mezery, bez změny logiky).
refactor-Refaktoring kódu (ani bugfix, ani feat).
perf-Změna kódu pro zvýšení výkonu.
test-Přidání nebo oprava testů.
build / ci-Změny v buildu, závislostech nebo CI/CD skriptech.
chore-Ostatní úpravy neměnící produkční kód.

Příklady:

feat(auth): přidáno přihlášení přes Google
fix(parser): oprava přetékání řetězce
feat(api)!: změna struktury odpovědi (BREAKING CHANGE)

Vytvářecí vzory (Creational Patterns) Creational

Řeší mechanismy vytváření objektů, zvyšují flexibilitu a opakovatelnost kódu.

Vzor Účel / Popis
Factory Method Definuje rozhraní pro vytváření objektu, ale nechává podtřídy rozhodnout, kterou třídu instancovat.
Abstract Factory Umožňuje vytvářet rodiny souvisejících nebo závislých objektů bez specifikování jejich konkrétních tříd.
Builder Odděluje konstrukci složitého objektu od jeho reprezentace, což umožňuje stejným konstrukčním postupem vytvářet různé reprezentace.
Prototype Umožňuje kopírovat existující objekty bez závislosti na jejich konkrétních třídách (klonování).
Singleton Zajišťuje, že třída má pouze jednu instanci, a poskytuje k ní globální přístupový bod.

Příklad: Singleton (TypeScript)

class Database {
  private static instance: Database;

  private constructor() { /* privatni konstruktor */ }

  public static getInstance(): Database {
    if (!Database.instance) {
      Database.instance = new Database();
    }
    return Database.instance;
  }
}

Strukturální vzory (Structural Patterns) Structural

Vysvětlují, jak skládat objekty a třídy do větších struktur při zachování pružnosti a efektivity.

Vzor Účel / Popis
Adapter Umožňuje objektům s nekompatibilním rozhraním spolupracovat (převodník/adaptér).
Bridge Rozděluje velkou třídu nebo sadu souvisejících tříd na dvě samostatné hierarchie (abstrakce a implementace), které lze vyvíjet nezávisle.
Composite Umožňuje skládat objekty do stromových struktur a pracovat s jednotlivými objekty i celými strukturami stejně.
Decorator Umožňuje dynamicky přidávat objektům nové funkčnosti zabalením do nových objektů (wrappery).
Facade Poskytuje zjednodušené rozhraní ke složitému systému tříd, knihovně nebo frameworku.
Flyweight Šetří paměť sdílením společných částí stavu mezi velkým množstvím objektů.
Proxy Poskytuje zástupce nebo objektový "zástupný symbol" pro jiný objekt za účelem řízení přístupu k němu.

Příklad: Decorator (TypeScript)

interface Coffee { getCost(): number; }

class SimpleCoffee implements Coffee {
  getCost() { return 10; }
}

class MilkDecorator implements Coffee {
  constructor(private coffee: Coffee) {}
  getCost() { return this.coffee.getCost() + 2; }
}

Vzor chování (Behavioral Patterns) Behavioral

Zabývají se efektivní komunikací a dělbou odpovědností mezi objekty.

Vzor Účel / Popis
Chain of Responsibility Umožňuje předávat požadavky podél řetězce zpracovatelů. Každý zpracovatel se rozhodne, zda požadavek zpracuje nebo předá dál.
Command Mění požadavek na samostatný objekt obsahující všechny informace o požadavku (umožňuje undo/redo, fronty...).
Iterator Umožňuje procházet prvky kolekce, aniž by vystavoval její vnitřní reprezentaci.
Mediator Omezuje přímou komunikaci mezi objekty a nutí je spolupracovat výhradně prostřednictvím objektu mediátoru.
Memento Umožňuje uložit a obnovit předchozí stav objektu bez porušení zapouzdření.
Observer Definuje mechanismus odběru pro upozorňování více objektů o jakýchkoli událostech, které se stanou v pozorovaném objektu.
State Umožňuje objektu změnit své chování při změně jeho vnitřního stavu (vypadá, jako by změnil svou třídu).
Strategy Definuje rodinu algoritmů, zapouzdří každý z nich a dělá je vzájemně zaměnitelné.
Template Method Definuje kostru algoritmu v nadtřídě, ale nechává podtřídy přepsat konkrétní kroky bez změny struktury.
Visitor Umožňuje oddělit algoritmy od objektů, na kterých pracují (přidává nové operace bez úpravy tříd).
